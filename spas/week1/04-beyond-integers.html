Beyond Integers

Estimated time: ~2.5 hours  |  Sections: 1.8–1.11  |  Prerequisite: SPA 2 (Converting Between Bases)

What We Have / What We Can't Do / What We Can Now Do

What you already know: You can represent any non-negative integer in binary, hex, and octal. You understand unsigned integer range and overflow from SPA 2. You may also have completed SPA 3 on signed integers and two's complement.

What you can't do yet: Explain how a computer stores the number 3.14, the letter 'B', or the string "Hello". You also can't read a memory dump and tell what data is stored at a given address.

What you will be able to do by the end of this SPA: Represent floating-point numbers in IEEE 754 format. Map characters to their ASCII/UTF-8 byte values. Read a memory layout and identify arrays, strings, and simple records. Most importantly, you will see that the same byte pattern can mean completely different things depending on context — the central idea of this entire course.

So far, you have learned how computers represent integers — both unsigned and signed. But integers are only one kind of data. A computer also needs to store:

  • Fractional numbers (like 3.14 or 0.001)
  • Characters and strings (like 'A' or "Hello")
  • Complex data structures (arrays, records, structs)

This SPA extends the "bits represent data" idea to all of these cases — and then ties everything together with a synthesis section that demonstrates the core principle: the bits don't carry meaning. The context does.

1.8 — Floating-Point Representation (IEEE 754, Conceptual)

Not all numbers are integers. How does a computer represent 3.14, 0.001, or 6.022 × 1023?

The answer is scientific notation, but in binary. Just as 6.02 × 1023 in decimal scientific notation has a mantissa (6.02) and an exponent (23), binary floating point stores a significand and an exponent — both in binary.

IEEE 754 Single Precision (32-bit) Structure

| Sign (1 bit) | Exponent (8 bits) | Significand (23 bits) |
|      S       |       E        |         M            |
  • Sign bit: 0 = positive, 1 = negative
  • Exponent: Stored with a bias of 127 (so the range 1–254 maps to exponents −126 to +127). This avoids needing a signed exponent field.
  • Significand: The fractional part of the number. The leading 1 is implicit (not stored), giving an extra bit of precision.

Example: 6.5 in IEEE 754 Single Precision

  1. 6.5 in binary = 110.1
  2. Normalize: 1.101 × 22
  3. Sign = 0 (positive)
  4. Exponent = 2 + 127 = 129 = 10000001
  5. Significand = 10100000000000000000000 (the bits after the leading 1)
  6. Full 32-bit pattern: 0 10000001 10100000000000000000000

Key Insight — Precision is Limited

Just as you can't write 1/3 exactly in decimal (0.333...), you can't represent all fractional values exactly in binary. The number 0.1, for example, is an infinite repeating fraction in binary. This is why 0.1 + 0.2 != 0.3 in many programming languages — not a bug, but a consequence of finite binary representation.

Why This Matters

The hardware for binary floating-point arithmetic is fundamentally different from integer arithmetic. The same "context determines meaning" principle applies: the CPU treats the 32 bits differently depending on whether the instruction says "add these as integers" or "add these as floats."

1.9 — Character Encoding: ASCII and UTF-8

How does the computer store the letter 'A'? It doesn't store a picture of the letter. It stores a number — specifically, the number 65, which in 8-bit binary is 01000001.

ASCII (American Standard Code for Information Interchange)

A 7-bit encoding (stored in 8-bit bytes) that maps 128 values to English letters, digits, punctuation, and control characters:

CharacterDecimalHexBinary
'0'480x3000110000
'A'650x4101000001
'a'970x6101100001
' ' (space)320x2000100000

Notice the patterns: 'A' through 'Z' are sequential (65–90). 'a' through 'z' are sequential (97–122). Digits '0'–'9' are sequential (48–57). These patterns are not accidents — they make character manipulation in code simpler.

UTF-8

ASCII only covers 128 characters — enough for English, but not for accented characters, Chinese, emoji, etc. UTF-8 is a variable-length encoding that is backward-compatible with ASCII (the first 128 code points are identical) and can represent over a million Unicode characters using 1–4 bytes per character.

Key idea: In UTF-8, a single "character" (code point) may occupy multiple bytes in memory. The byte 0x41 is always 'A' — whether the file is ASCII or UTF-8. Non-ASCII characters use multi-byte sequences where the leading bits of each byte signal how many bytes are in the sequence.

Forward Reference

In Week 8, when you write MIPS programs that manipulate strings, you will load individual bytes from memory using lb (load byte) and interpret them as ASCII character codes. The CPU doesn't know the difference between loading the byte 0x41 as the number 65 or as the character 'A' — the instruction you choose determines the interpretation.

1.10 — Memory Layout: Arrays and Simple Records

Memory is a long, flat array of bytes. Each byte has a unique address, starting from 0. When you store a multi-byte value (like a 32-bit integer or a string), it occupies consecutive bytes.

Contiguous Layout

An array of four 32-bit integers starting at address 1000:

AddressContent (hex)Value (decimal, unsigned)
100000 00 00 055 (array[0])
100400 00 00 0A10 (array[1])
100800 00 00 0F15 (array[2])
101200 00 00 1420 (array[3])

Each integer is 4 bytes (32 bits = 1 word). The array elements are stored back-to-back with no gaps. To access array[i], the CPU computes the address as base_address + i × element_size.

Strings in Memory

The C string "Hi" stored starting at address 2000:

AddressContent (hex)ASCII Character
200048'H'
200169'i'
200200'\0' (null terminator)

Strings are arrays of bytes (characters), terminated by a null byte (0x00). This is how C and MIPS handle strings — there is no separate "string type" in memory. A string is just a sequence of bytes that happens to end with zero.

Simple Records (Structs)

A record with a character and an integer:

struct { char c; int x; }

Stored contiguously, starting at address 3000:

AddressContent (hex)Field
300041c = 'A' (1 byte)
300100padding (alignment)
300200padding (alignment)
300300padding (alignment)
300400 00 00 1Ex = 30 (4 bytes)

Note the padding bytes between c and x. MIPS requires word-aligned access for 32-bit integers (addresses must be multiples of 4). The compiler inserts padding to satisfy this alignment requirement.

Decoder Preview

In later weeks, you will build the hardware that uses memory addresses to select specific bytes. We will use decoder circuits for this selection — not multiplexers. You will learn why in Week 3.

1.11 — Synthesis: The Same Byte, Four Meanings

Here is the idea that holds the entire course together:

The Core Principle

The byte 01000010 can be:

  • The unsigned integer 66
  • The signed integer 66 (positive, since MSB is 0)
  • The ASCII character 'B'
  • The hex value 0x42
  • A color channel value (66 out of 255, a dim green in RGB)
  • Part of a MIPS instruction (the opcode or register field, depending on position)

The bits are identical. The meaning changes based on context — specifically, on what the CPU is told to do with them.

When a MIPS instruction says add $t0, $t1, $t2, the CPU treats the 32-bit contents of registers $t1 and $t2 as signed integers. When the instruction says lb $t0, 0($s0), it loads one byte from memory and sign-extends it — treating that byte as a signed 8-bit value. When the instruction says lw $t0, 0($s0), it loads four bytes and treats them as a 32-bit word.

The hardware doesn't know what your data is. It only follows the instructions you give it. This is why understanding data representation is not just a "first week topic" — it is the lens through which every subsequent topic in this course makes sense.

Forward Reference: Von Neumann Architecture

In Week 9, you will learn about the fetch-decode-execute cycle. During the "fetch" phase, the CPU reads bytes from memory and interprets them as instructions — not data. The exact same byte pattern that means "66" as data means "execute this operation" as an instruction. This is the Von Neumann architecture: program and data share the same memory.
